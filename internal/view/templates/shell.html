{{/* The shell: the document the application is served inside. Every name here is an address a plugin can take over. The bodies are thin on purpose — a name exists so it can be replaced, and a big body is a big thing to reproduce when you only wanted to change one part of it. What this does NOT do is reproduce the application's own head. Vite writes hashed asset names into it on every build, and a template that restated them would be a second place the build output has to be kept true. It is carried through as .AppHead instead: opaque to us, replaceable by an override, and never a thing anybody has to keep in step with a bundler. */}} {{define "cog.shell.document"}} {{template "cog.shell.head" .}} {{template "cog.shell.body" .}} {{end}} {{define "cog.shell.head"}}{{.AppHead}} {{template "cog.shell.tokens" .}} {{range .Styles}} {{end}}{{range .Scripts}} {{end}}{{template "cog.slot.head" .}}{{end}} {{/* Tokens are their own name for one reason: overriding this single template restyles the whole product, in both light and dark, with no code at all. It is the cheapest thing a plugin can do and the most visible. The host's own body is empty because the application still ships its own palette inside its stylesheet. This name exists so a plugin can add one above it, and so the palette has somewhere to move to when it is lifted out. */}} {{define "cog.shell.tokens"}}{{end}} {{/* The body is whatever was rendered into it. A plugin page puts its own output here; the application puts its mount point here once it is served through this shell rather than beside it. */}} {{define "cog.shell.body"}}{{.Body}}{{end}} {{/* Append slots. Definitions of these CONCATENATE rather than replace, so two plugins contributing to the same place both survive and neither had to know the other existed. The host's own bodies are empty on purpose: an extension point has to exist before anybody can extend it. */}} {{define "cog.slot.head"}}{{end}}
