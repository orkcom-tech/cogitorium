Two things about this deployment that are not preferences:

  1. One replica, always. Everything is stored in SQLite with a single writer,
     so two pods on one volume corrupt it. The Deployment is pinned and the
     strategy is Recreate.

  2. Gears are NOT isolated here. Off-cluster they run in a throwaway container
     with no network and none of the server's files; there is no Docker in a
     pod, so in-cluster they run as a subprocess with the server's own access —
     including the database and the provider keys in it. Approving a gear in
     this deployment grants it everything the server has. Gear execution as
     Kubernetes Jobs is the fix; it is designed and not built.

     Because of that, this chart refuses to enable the in-UI terminal or the
     outward gate at all.
